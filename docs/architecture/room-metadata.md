# 객실 메타데이터 (#328)

기존 객실 등록 `POST /api/v1/accommodations/{id}/rooms`, 수정 `PUT /api/v1/rooms/{id}`의
`metadata`에 아래 값을 선택적으로 전달합니다. 쓰기 권한은 기존과 동일하게 `ADMIN`입니다.
공개 `GET /api/v1/rooms/{id}`와 등록·정보 수정·상태 변경 응답에서만 등록된 객체를 반환합니다.
객실 목록·가용 객실·숙소 검색에는 메타데이터 필드, 필터, 정렬을 추가하지 않습니다.
기존 ID·기본가·수용 인원·편의시설·상태·대표 이미지와 이미지 순서는 그대로입니다.

| 필드 | 타입과 규칙 |
| --- | --- |
| `description` | 일반 텍스트, 최대 1000 UTF-16 단위 |
| `bedConfiguration` | 일반 텍스트, 최대 100 단위. 예: `퀸 1개, 싱글 1개`. 객실 수용 인원을 계산하지 않음 |
| `areaSquareMeters` | ㎡, `DECIMAL(6,2)`, 0.01~9999.99, 소수 두 자리까지. API는 반올림하지 않음 |
| `view` | 일반 텍스트, 최대 100 단위. 예: `바다 전망`. 객실 이름이나 사진에서 추정하지 않음 |

길이는 입력 원문 기준이며, 텍스트는 앞뒤 공백을 제거하고 빈 결과를 미입력으로 처리합니다.
모든 값이 미입력이면 응답에서 `metadata`를 생략합니다. 일부만 입력한 객체는 나머지 필드가 `null`입니다.
필드 검증 실패는 기존 `400 COMMON_001`과 `metadata.<필드명>`을 반환합니다.

| PUT의 `metadata` | 의미 |
| --- | --- |
| 생략 또는 `null` | 저장값 보존. 기존 클라이언트 PUT 호환 |
| 일부 또는 전체 필드가 든 객체 | 메타데이터 전체 교체. 객체 안에서 생략하거나 `null`인 필드는 삭제 |
| `{}` | 메타데이터 모두 삭제 |

기존 이름·인원·가격 등의 PUT 의미는 바뀌지 않습니다. 구버전 프론트엔드는 새 필드를 보내지
않아 보존됩니다. 후속 화면 작업은 상세 조회의 실값만 표시하고, 관리자 편집에서 변경하지 않은
값은 유지해야 합니다. 부분 변경을 제출한다면 먼저 읽은 값과 조합하거나, 의도한 전체 교체임을
사용자에게 알려야 합니다. 목록 응답만으로는 현재 메타데이터를 알 수 없습니다.

## 기존 MySQL 업그레이드

신규 스키마의 JPA 매핑은 nullable 컬럼과 `chk_rooms_metadata_values`를 정의합니다.
기존 DB는 운영 절차에 따라 백업하고 쓰기를 중단한 상태에서, **새 앱 첫 실행 전에**
[일회성 SQL](../erd/mysql-room-metadata-upgrade.sql)을 한 번 실행합니다. `ddl-auto=update`가
기존 테이블의 CHECK를 보장하지 않습니다. 이미 컬럼 일부가 생성됐다면 SQL을 그대로 재실행하지
말고 `SHOW CREATE TABLE rooms`의 결과와 비교해 빠진 항목만 적용합니다. MySQL DDL은 자동 커밋됩니다.

1. 적용 전 `SHOW CREATE TABLE rooms;`로 네 컬럼 및 CHECK의 부재를 확인합니다. `SELECT COUNT(*) FROM rooms;`
   결과와 기존 객실 ID·가격·상태·사진 연결 표본을 기록합니다.
2. SQL 적용 뒤 `SHOW CREATE TABLE rooms;`에서 네 nullable 컬럼, 면적 `DECIMAL(6,2)`, CHECK를 확인합니다.
   같은 수와 표본이 유지되고 기존 행의 네 컬럼은 모두 `NULL`이어야 합니다. 별도 백필은 하지 않습니다.
3. 격리 또는 스테이징에서 기존 요청과 메타데이터 등록·수정·삭제, 상세 조회를 확인한 뒤 쓰기를 재개합니다.
   구버전 앱으로 롤백해도 컬럼을 삭제하지 않습니다. 컬럼을 제거하면 새로 입력한 데이터가 손실됩니다.

## 상세 캐시

Room detail은 `reservation:cache:v3:room-detail::{id}`를 사용하고 Accommodation detail은 v2를 유지합니다.
기존 JSON은 새 DTO에서 메타데이터가 없는 값으로 역직렬화할 수 있지만, v2 Room 키는 읽지 않아 배포 전
응답이 새 상세를 가리지 않습니다. 과거 키는 TTL로 만료시키며 flush하지 않습니다. 같은 Room의 정보·상태·사진
수정은 기존 트랜잭션 인식 무효화를 그대로 사용합니다. 커밋 뒤에만 새로 읽고, 롤백이면 이전 상세가 유지됩니다.
구버전으로 되돌리면 TTL 동안 기존 v2 스냅샷이 남을 수 있으므로 롤백 시에는 Room의 구버전 키만 별도로 확인합니다.

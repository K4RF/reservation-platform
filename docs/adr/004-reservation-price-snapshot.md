# ADR-004: 예약 가격 Snapshot을 숙박일별 행과 총액으로 저장

## 상태

Accepted

## 배경

객실은 기본 1박 가격과 날짜별 덮어쓰기 가격을 가집니다. 예약 생성 후 원본 가격이
변경되어도 확정된 예약 금액은 바뀌면 안 되며, 일정 변경 시에는 변경 시점의 새
기간 가격으로 다시 계산해야 합니다.

## 결정

- 숙박일은 `[checkInDate, checkOutDate)`로 계산합니다.
- 각 숙박일에 날짜별 가격이 있으면 해당 가격을, 없으면 객실 기본 가격을
  적용하고 모든 숙박일 가격을 더합니다.
- `nightly_price_snapshot`에는 계산 시점의 첫 숙박일 적용 가격을 저장합니다.
- `total_amount`에는 모든 숙박일 가격을 합한 확정 금액을 저장하며, 이후 금액
  판단의 기준 Snapshot으로 사용합니다.
- 각 숙박일의 날짜와 적용 가격을 `reservation_nights`에 저장합니다. 같은 예약과
  날짜는 하나만 존재하며, `total_amount`는 숙박일별 가격 합계와 일치해야 합니다.
- 일정 변경은 새 기간 전체를 변경 시점 가격 정책으로 다시 계산해 첫날 가격,
  총액과 숙박일별 Snapshot을 모두 교체합니다. 기존 기간과 겹치는 날짜도 과거
  가격을 유지하지 않습니다.
- `Reservation`이 `ReservationNight` 생명주기를 소유하며, 일정 변경 시 빠진
  날짜는 orphan removal로 삭제하고 겹치는 날짜는 갱신하며 새 날짜는 추가합니다.
- 가격은 `BigDecimal` 덧셈만 사용합니다. 입력·저장 가격이 소수 둘째 자리로
  제한되므로 나눗셈이나 별도 반올림 정책은 적용하지 않습니다.

## 대안

- 첫 숙박일 가격과 총액만 저장: 행 수는 적지만 날짜별 가격을 사용한 과거 예약의
  상세 금액 구성을 정확히 복원할 수 없습니다.
- 총액만 저장: 가장 단순하지만 기존 `nightlyPriceSnapshot` 응답의 의미를 잃고
  대표 1박 가격을 제공할 수 없습니다.

## 결과와 한계

객실 기본 가격이나 날짜별 가격이 바뀌어도 기존 예약의 숙박일별 가격, 첫 숙박일
가격과 총액은 유지됩니다. 상세 조회에서 확정된 일자별 가격 구성을 제공할 수 있고,
향후 일자별 부분 환불의 근거로 사용할 수 있습니다. 대신 예약 숙박일 수만큼 행이
추가되고 일정 변경 시 자식 행 관리가 필요합니다.

이 결정 이전에 생성된 예약은 첫 숙박일 가격과 총액만으로 실제 일자별 가격 구성을
정확히 역산할 수 없습니다. 따라서 업그레이드 SQL은 과거 `ReservationNight`를
임의 생성하지 않고, 신규 예약과 일정 변경된 예약부터 완전한 Snapshot을 보장합니다.

# ADR-004: 예약 가격 Snapshot을 첫 숙박일 가격과 총액으로 저장

## 상태

Accepted

## 배경

객실은 기본 1박 가격과 날짜별 덮어쓰기 가격을 가집니다. 예약 생성 후 원본 가격이
변경되어도 확정된 예약 금액은 바뀌면 안 되며, 일정 변경 시에는 변경 시점의 새
기간 가격으로 다시 계산해야 합니다.

## 결정

- 숙박일은 `[checkInDate, checkOutDate)`로 계산합니다.
- 각 숙박일에 날짜별 가격이 있으면 해당 가격을, 없으면 객실 기본 가격을
  적용하고 모든 숙박일 가격을 더합니다.
- `nightly_price_snapshot`에는 계산 시점의 첫 숙박일 적용 가격을 저장합니다.
- `total_amount`에는 모든 숙박일 가격을 합한 확정 금액을 저장하며, 이후 금액
  판단의 기준 Snapshot으로 사용합니다.
- 일정 변경은 새 기간 전체를 변경 시점 가격 정책으로 다시 계산해 두 Snapshot을
  교체합니다. 기존 기간과 겹치는 날짜도 과거 가격을 유지하지 않습니다.
- 날짜별 상세 가격을 Reservation 하위 테이블로 복제하지 않습니다.
- 가격은 `BigDecimal` 덧셈만 사용합니다. 입력·저장 가격이 소수 둘째 자리로
  제한되므로 나눗셈이나 별도 반올림 정책은 적용하지 않습니다.

## 대안

- 날짜별 가격 Snapshot 행 저장: 상세 내역을 완전히 재현할 수 있지만 현재 조회와
  취소 정책에는 확정 총액만 필요하며, 행 수와 저장·변경 복잡도가 증가합니다.
- 총액만 저장: 가장 단순하지만 기존 `nightlyPriceSnapshot` 응답의 의미를 잃고
  대표 1박 가격을 제공할 수 없습니다.

## 결과와 한계

객실 기본 가격이나 날짜별 가격이 바뀌어도 기존 예약의 첫 숙박일 가격과 총액은
유지됩니다. 별도의 날짜별 Snapshot 행 없이 현재 Schema와 API 호환성을 유지할 수
있습니다. 반면 과거의 숙박일별 세부 가격 구성은 Reservation만으로 복원할 수
없습니다. 향후 일자별 부분 환불이나 가격 명세가 필요해지면 별도 Snapshot 테이블을
Migration으로 추가해야 합니다.

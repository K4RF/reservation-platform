# 공개 숙소 검색의 목적지와 복귀 (#320)

Home과 Search의 목적지 입력은 조회 결과가 아닌 초안입니다. 후보를 강조하거나 선택해도 URL과 기존
숙소 결과는 바뀌지 않습니다. 검색을 제출하면 위치·날짜·인원 초안을 적용하고 결과를 다시 조회합니다.
Search에서는 숙소명·가격·편의시설·정렬·페이지 크기 등 이미 적용된 조건을 유지하고 페이지를 0으로 돌립니다.
상세 필터와 정렬은 아직 제출하지 않은 목적지 초안을 적용하지 않습니다.

| 제출 또는 진입 방식 | URL 및 API 조건 |
| --- | --- |
| 직접 입력 | `destination`만 적용. 유니코드 공백을 정리하고 원문 최대 UTF-16 100단위를 검사. 후보가 없는 한 글자도 검색 가능 |
| 후보 선택 | `country`, `city`, 지역 후보의 `region`, `status=ACTIVE`. 표시 이름은 URL에 따로 저장하지 않음 |
| 선택 후 수정·삭제 | 수정 시 정확 위치 값을 모두 빼고 `destination` 사용. 공백만 남기거나 삭제하면 위치 조건 전체를 제거 |
| 기존 `city`/`region` 링크 | 기존 정확 조건으로 사용. 목적지 입력을 변경하지 않은 날짜·인원 제출이나 필터 변경은 기존 위치 유지 |

후보의 정규값이 표시 이름과 별개로 유지됩니다. 공유 URL에서 후보 도시·지역의 표시 이름은
저장된 `city`·`region`에서 복원하고, 요약은 국가·부모 도시를 함께 포함합니다. 목적지를 바꾸면 기존
위치 조건을 교체합니다. 레거시 `region` 편집은 기존 방식의 상세 필터에만 표시해 새 목적지와 충돌하지 않게 합니다.
후보 제출은 활성 카탈로그 계약에 맞춰 `ACTIVE`로 전환하며, 그 뒤 사용자가 별도로 운영 상태를 바꾸는 것은 허용합니다.

공개 URL에서 비어 있지 않은 `destination`과 `country/city/region`을 혼합하거나, `city` 없이 `country`를
지정하거나, 단일 필드를 중복 지정하면 조회하지 않고 오류를 표시합니다. 비어 있는 선택적 위치 문자열은
조건으로 보지 않습니다. 새 키는 공개 검색에만 허용됩니다. 관리자는 기존 정확 `city/region` 필터를 유지합니다.

카드 링크의 `search`에는 기존 canonical 검색 쿼리를 사용합니다. 상세에서 날짜·인원을 바꿔도 원래 검색의
목적지·정렬·필터·페이지가 유지됩니다. 같은 문서에서 검색 결과가 다시 로드된 뒤 카드 포커스와 스크롤을 복원합니다.
새로고침은 URL 조건만 복원합니다. 로그인 복귀의 가용성 재조회와 예약 안전 조건은 그대로입니다.
토큰, 대표 투숙객 정보, 표시용 후보 객체를 URL에 추가하지 않습니다.

## 검증

- 기존 `searchQuery`, `bookingContext`, `AccommodationSearchNavigation`, `BookingCreationFlow`, 관리자 Suite에서
  충돌·중복 거절, 선택과 편집, 결과/URL 복원, 필터와 페이지, 상세·로그인 복귀 및 가용성 재조회를 검증합니다.
- 격리 Chromium UI Audit에서 승인된 Navy & Ivory 검색창 배치를 유지한 채 1440px Home 후보 선택·제출,
  상세 복귀와 카드 포커스, 390px Search 직접 링크·편집·삭제를 확인했습니다. 사진과 후보는 Fixture이며,
  브라우저의 실제 서버 통신이나 외부 OAuth 검증은 아닙니다. Browser Audit은 `MemoryRouter`를 사용하므로
  주소창 대신 카드의 canonical 복귀 링크를 확인했고, History 뒤/앞 이동은 Vitest에서 검증했습니다.

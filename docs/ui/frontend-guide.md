## 화면과 상태 책임

| 화면 | 유지할 계약 |
| --- | --- |
| 공통 | `SiteHeader`는 Desktop/Mobile 내비게이션, `RootLayout`은 프레임과 인증/로그아웃을 담당한다. 모달을 닫으면 포커스와 스크롤 잠금을 복구한다. |
| Home | A1 Hero 안에 검색을 배치한다. Hero는 AI 장식 이미지이며 실제 숙소가 아니다. 사진 탐색은 ID 순 ACTIVE 목록의 첫 2건까지만 사용하며 순위·가격을 추측하지 않는다. |
| Search | `CompactSearchBar`는 입력, `SearchLayer`는 레이어 표시를 맡는다. 날짜·인원·필터의 초안, 적용값, 제출된 URL을 분리한다. 미리보기·취소·초안 초기화는 조회하지 않는다. 정렬은 적용값 기준이며 상세에서 돌아올 때 원래 검색 위치와 포커스를 복구한다. |
| Detail | 날짜 미적용 시 읽기 전용 객실, 적용 후에는 가용 목록 하나를 표시한다. Gallery는 선택을 바꾸지 않는다. 모바일 CTA는 적용 전 일정 입력, 적용 후 가용 목록, 명시적 객실 선택 후 계속하기로 이동한다. 로그인 뒤 새 가용성 조회로 선택을 검증한다. |
| Booking | `BookingPriceSession`은 상세와 Booking 단계 사이에 가격 조회를 공유한다. 예상 합계와 저장 금액을 구분하고 완료는 본인 예약 GET이 판단한다. 쓰기 진행/결과 불명 상태에서는 편집·재제출·내부 객실 복귀를 잠근다. |
| 내 예약 | 카탈로그의 현재 사진과 저장된 예약 가격·투숙객·정책을 구분한다. 변경·취소 준비는 상호 배타적이며, 실패 후 취소하려면 새 본인 상세 GET과 재확인이 필요하다. 예상 환불은 실제 결제 환불이 아니다. |
| Auth | 비인증 페이지는 브랜드 프레임을 사용한다. 가입 후 로그인으로 안내하되 자동 로그인하지 않는다. 복귀 URL에 토큰·대표 투숙객 데이터를 넣지 않는다. |
| ADMIN | 조회·초안·쓰기 잠금은 현재 관리 페이지에 남긴다. 입력 작업을 바꾸는 중에도 대기·결과 불명·사진 복구를 우회할 수 없다. 정책 GET/삭제, 전체 예약 관리, 가격·재고 일괄 편집은 없다. |

날짜 범위는 최소 1박이며 필요한 경우 체크인 변경 시 체크아웃을 다음 날로 보정한다.
인원은 성인·아동 구분 없는 양의 정수다. Home/Search에서는 생략할 수 있다.
미리보기는 선택을 바꾸지 않으며 Detail에서 다른 조건을 적용하면 기존 가용성·선택·요금은 무효다.
[검색 복귀](../testing/frontend-exploration-return-context.md) 및
[객실 상세와 선택](../testing/frontend-room-detail-selection.md)에서 URL·포커스 계약을 확인할 수 있다.

## 데이터와 실패 복구

- [공개 Media 계약](../architecture/catalog-media.md)에 있는 사진만 표시한다. 사진 없음/실패를
  가짜 매물 사진으로 채우지 않는다. 목록 최저가·통화·리뷰·객실 Bed/Size/View는 추측하지 않는다.
- [ADMIN 앨범](../architecture/media-management.md)은 최신 GET의 강한 ETag로 쓰기를 준비한다.
  쓰기 실패·결과 불명 이후에는 GET으로 다시 확인하고 새 리뷰를 거친다. 자동으로 재전송하지 않는다.
- 예약 생성·변경·취소·관리 쓰기는 401을 포함해 자동 재실행하지 않는다. 네트워크 오류나 이탈은
  서버 롤백을 뜻하지 않는다. Loading/Error/Empty 컴포넌트는 표시만 맡고 요청·잠금을 소유하지 않는다.
- 예약 생성 404/409는 현재 확인 화면의 투숙객 입력을 유지하지만 기존 선택으로 재제출하지 못한다.
  사용자가 가용 객실을 다시 조회하면 투숙객 입력과 이전 객실·가격 선택을 폐기하고 같은 날짜·인원으로
  새 GET을 수행한다. 성공 결과에서 객실을 다시 선택하고 확인해야 제출할 수 있다.

## 검수 시 확인할 항목

- 원본과 실제 경로의 1440/390px을 같은 시작 위치에서 비교한다. 시안 도구는 제외한다.
  사진 있음·없음·실패, 로딩·빈 결과·오류, 긴 이름·이메일·예약번호를 함께 확인한다.
- 320px·확대·짧은 높이에서 키보드 조작과 Escape/포커스 복귀를 확인한다. Sticky Rail이나
  Fixed CTA가 입력·오류를 가리지 않아야 한다. 가로로 넓은 요금·재고 표는 이름 있는 내부 영역에서만
  스크롤한다. 문서 가로 넘침을 숨기지 않는다.
- 실제 쓰기는 일회용 DB·Redis·파일 저장소에서만 검증한다. ADMIN 사진 등록·대표 변경 → 공개
  목록/상세 → 로그인 후 fresh availability → 예약 완료/본인 조회를 확인한다.
  기존 자동 HTTP 검증은 `MediaManagementMySqlIntegrationTest`에 있다.
- 격리 Fixture의 성공은 실제 HTTP, 외부 Google OAuth, 운영 자산 성능을 대신하지 않는다.
  실기기·브라우저 줌·가상 키보드·safe area·보조 기술과 사진 권리/크롭은 별도 확인한다.
  자동 테스트 통과나 개발자 검증은 f0.6.0 사용자 최종 시각 승인이 아니다.

색·타이포그래피의 단일 원본은 `frontend/src/styles/tokens.css`이다.
`frontend/src/index.css`의 동적 상태 클래스는 JSX 문자열 조합 사용처를 확인한 뒤 정리한다.
화면 비교용 일회성 캡처와 실행 결과는 PR/이슈에 첨부하고 저장소에는 승인 원본·재현 절차·계약을 남긴다.
